# Запуск проекта

## 1 Локальная проверка

Откройте index.html в браузере. Для полноценной проверки хранилища, PDF, буфера обмена и запросов используйте локальный HTTP-сервер: `python -m http.server 8000` из каталога проекта. Сайт работает без сборки. Форма не имитирует запись: без адреса приёмника она сообщает о недоступности онлайн-записи.

## 2 Google Таблица и Apps Script

1. Импортируйте docs/zerno7-leads.xlsx как Google Таблицу «Zerno7 — Leads». В файле есть листы leads, crm_import, status_map и utm. Откройте Расширения → Apps Script и вставьте apps-script/Code.gs.
2. В свойствах скрипта добавьте SPREADSHEET_ID — идентификатор этой таблицы. Пароли, токены и ключи в файлы проекта не вставлять.
3. Выполните setupWorkbook от имени владельца. Подтвердите доступ скрипта к своей таблице. Скрипт проверяет заголовки leads и настраивает правила ввода и подсветку. Формулы crm_import рассчитаны на первые 200 строк. При расширении перенесите формулы вниз и проверьте результат.
4. Разверните как веб-приложение с выполнением от владельца. Для работы формы посетитель должен иметь право вызывать приёмник. Используйте отдельную учебную таблицу и только тестовые данные.
5. В js/config.js внесите полученный HTTPS-адрес /exec в leadEndpoint. После обновления серверного кода обновляйте развёртывание.
6. С Vercel отправьте тестовую заявку. Проверьте читаемый JSON с ok: true и фактическую строку. Проверьте повтор запроса с тем же request_id, пустой телефон, телефон 123 и отказ сети. Не заменять проверку ответа режимом no-cors.

ContentService перенаправляет ответ на googleusercontent.com; браузерная проверка с опубликованного домена обязательна. Сетевой запрос, который ушёл, но ответ которого нельзя прочитать, не считается подтверждением успеха.

## 3 GA4

Создайте отдельный ресурс «ЗЕРНО 7 — сайт», часовой пояс Москва, валюта RUB, веб-поток с опубликованным адресом. Включите расширенную статистику и взаимодействия с формами. Добавьте реальный Measurement ID в js/config.js. analytics.js подключён в head всех девяти страниц и загружает тег только с корректным ID. Без ID аналитика никуда не отправляется.

Зарегистрируйте event-scoped параметры button_name, page_section, course_name, quiz_result, lead_course, bean_name, messenger. Ключевые события — только generate_lead, contact_click, messenger_click. Автоматические события не дублировать вручную. Для асинхронной формы отдельно проверить form_start и form_submit.

В DebugView проверьте все 18 событий и сохраните кадры. Временно используйте Google Analytics Debugger; после испытаний отключите. Выдайте преподавателю Viewer к нужному ресурсу. Не публикуйте персональные данные посетителей.

## 4 GitHub и Vercel

Создайте публичный репозиторий tz-02-kofeynya-zerno7 и загрузите содержимое папки. Framework preset: Other. Build command: пусто. Output directory: корень проекта. Подключите main к Vercel. Публичную загрузку и доступы выполняет владелец аккаунта; в этом пакете они не выполнены.

В js/config.js внесите siteUrl, ссылки социальных страниц и мессенджеров. В og:image на страницах замените относительный адрес на абсолютный HTTPS-адрес опубликованного img/og.jpg. Проверьте редиректы и 404 в Vercel. Историю коммитов вести по фактическим изменениям — не создавать задним числом десять искусственных этапов.

## 5 Ссылки и QR

docs/utm.csv содержит структуру 12 размещений, но не рабочие URL. После публикации подставьте адрес Vercel, ники двух реальных партнёров, адреса и даты публикаций. utm_term оставлен пустым, поскольку платные ключевые слова не используются. Для U-10 и U-11 вместо пустого source внесите согласованные ники.

На листе utm полный URL собирается формулой из меток. Порядок столбцов соответствует CSV. Пример для строки 2: `=IF(OR(D2="",I2=""),"",$P$1&"/"&I2&"?utm_source="&ENCODEURL(D2)&"&utm_medium="&ENCODEURL(E2)&"&utm_campaign="&ENCODEURL(F2)&"&utm_content="&ENCODEURL(G2)&IF(H2="","","&utm_term="&ENCODEURL(H2)))` — в P1 хранится корень сайта без завершающего слеша. Разделители аргументов зависят от локали таблицы.

Короткие ссылки, QR U-12 и афиша создаются после получения окончательного адреса. QR для localhost, несуществующего домена или примерного адреса не выпускать. Проверять переход именно из публикации или сканированием.

## 6 CRM

Создайте воронку «Zerno7 · Школа бариста» и стадии из status_map. Добавьте свойства Request ID, Course, Start month, UTM Source, UTM Medium, UTM Campaign, UTM Content, Application Created At. Для Course значения совпадают с leads.

Лист crm_import строится формулами: TRIM убирает лишние пробелы, SPLIT разделяет имя, ARRAYFORMULA распространяет расчёт, VLOOKUP подставляет стадию из status_map. В русской локали используются эквиваленты СЖПРОБЕЛЫ и ВПР; разделители проверить в своей таблице. Неизвестную фамилию не выдумывать. Для сделки использовать название «Имя — курс — месяц» и сохранить request_id.

Экспортируйте CSV и выполните импорт связанных Contacts и Deals. Проверьте сопоставление, связь и обновление при повторном импорте. Пользовательское поле Request ID само по себе не делает импорт идемпотентным: используйте поддерживаемый уникальный идентификатор/Record ID. Для контактов без email проверьте выбранный способ идентификации. Проведите одну тестовую сделку до оплаты с заметками и задачей при предоплате; вторую закройте с причиной отказа. Статусы leads и CRM синхронизируются по регламенту, автоматически это не реализовано.

## 7 Финальная проверка

Проверьте страницы в 375, 768, 1280 px и Lighthouse на опубликованной версии. Требуемые пороги: Performance 70, Accessibility 90, SEO 90. Локальные программные тесты не заменяют DebugView, CRM, ManyChat и испытания И-01…И-13. Свободные места, каталог и сведения преподавателей требуют исходных данных — см. content-gaps.md.

Официальные справочные материалы: https://developers.google.com/apps-script/guides/content ; https://developers.google.com/apps-script/reference/lock/lock-service ; https://developers.google.com/analytics/devguides/collection/ga4/events .
